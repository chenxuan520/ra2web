# AI 信息边界修复与验证范围

2026-10-30（Asia/Shanghai）。这是用户明确要求不透视的正确性修复，依据源码、负向测试与真实引擎观察；不是高手战术研究全部完成，也不是新胜率。修复在实验分支，未推广 master 或上线。

## 已修正的入口

当前 normal/brutal 的集结、常规进攻兜底、持续主力搜索、辐射守备、地面静态防御与静态防空，共六个方向入口不再使用敌玩家的实际出生分配。统一从已揭示敌建筑或地图公开的未探可能出生点取得候选，稳定按距离与坐标排序；没有候选时走本方/既有安全兜底。敌我关系与是否参战是公开信息，敌现金、电力和实际起点不是。

这项改变会调整普通难度的旧行为，并可能改变随机位置选择的消耗次数，不能称与历史轨迹相同。防御建筑原来的随机角度/半径及真实合法摆放检查保留；公共候选不是已知敌基地。

区域威胁只统计己方与当前合法可见敌对象，再与真实空间查询相交。每轮 awareness 更新共享一次观察集合，下一轮重建；原始空间查询里的隐藏对象不会被读取并加入该缓存。审计未证实旧区域威胁缓存带来过实战增益，不作追溯收益推断。

扩张金额只计算当前合法可见格子。全部未知返回 `null`，可见空矿为0，局部可见是已知金额而非全区总量；重新被遮盖后不读取实时矿量。另修正历史单位混淆：MapApi 的矿量是矿包数，现按真实规则的矿石/宝石单价换算资金，再比较原有4000资金门槛；没有降低门槛。扩张完成与收基地的建筑条件只认己方建筑，不把隐藏敌基地/矿场当成己方设施。

## 验证方法

- 策略测试将外国玩家 `startLocation`、`credits`、`power` 敏感字段设为读取即失败；同合法信息、不同隐藏分配的六入口结果一致。另覆盖可见敌建筑正向变化、排序、无敌、全部已探、无效公共点和真实摆放 API 调用。
- 区域测试改变隐藏敌状态和矿量，确认不影响已知值；揭示后才变化。还覆盖矿石/宝石不同规则单价、富矿与空矿正向控制，以及敌建筑不触发己方扩张完成/收基地。
- [真实引擎脚本](../ts-redalert2/e2e/ai-information-boundary.ts)使用仓库实际合并规则、地图和地形资源与 `mp01t4` 的四个公开起点，己方固定0、敌方1/2，normal/brutal各一对。四个世界各180tick，每30tick记录合法观察、意图和实际指令。预置对象和无操作对手仅用于机制检验，不是付费经济或强度样本。
- 正向验证真实 shroud 显露敌工厂后方向改变，重新覆盖后回到公共未知方向；隐藏矿量变化不改变未知值，揭示后依真实规则计价；真实8×8富矿区能超过原4000门槛。

源码冻结为 [`183554e3105e6dd0e28b7f3d8d958841ebb7d0b7`](https://github.com/chenxuan520/ra2web/commit/183554e3105e6dd0e28b7f3d8d958841ebb7d0b7)。全量 Bun 测试322通过、13跳过、0失败；跳过项为需要额外配置的真实 PvPGN 与资源/HTTP 集成测试。entry/server/benchmark/fixture 类型检查和 build 通过。

根代理在源码提交后重跑真实引擎：4个世界、每个180tick/6快照/1实际指令，两profile各自的观察、意图和指令配对一致，敏感字段读取0、运行错误0。真实揭示的3包宝石按本仓规则为150资金，8×8富矿区11925资金；这只验证原4000门槛仍可达，不是已完成付费扩张。
