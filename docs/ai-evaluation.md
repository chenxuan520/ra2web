## 公平性与复现检查

- 所有正式局双方起始现金均为 10000，额外初始部队为 0，游戏引擎难度均为 `AiDifficulty.Normal`（数值 4）。`brutal` 仅选择 Bot 策略，不附带单方面经济或建造倍率；R2/R4 的直接对比双方均使用 brutal，对旧版时旧版保持 normal。对旧版的比较包含决策频率、操作和策略的整体变化，不能归因于单一算法。
- 每组对局同时交换出生点和更新顺序，所有逐玩家指标保持 `[candidate, baseline]` 顺序。程序检查已确认起始现金、阵营、完整成对赛程、槽位及坐标交换正确。`3497729` 同快照/同 profile 自对打中，所有采样和逐玩家统计在交换后精确镜像。
- `mp08t2` 使用出生点 `(27,50)` 与 `(82,87)`；`tn01t2` 使用 `(58,99)` 与 `(99,58)`。地图和地形档案 SHA-256 保存在逐局证据中；各轮基础规则与自定义规则 SHA-256 相同。
- R1/R2 开发报告的引擎提交为 `8fc9fc6`，R4 开发报告为 `1285f8b`，holdout 为 `16b5e81`，均记录 `engineDirty=false`。排除 Bot 与测试后，这三个引擎源码版本的差异为空；`16b5e81` 的 Bot 源码也与冻结候选 `04a9f7a` 相同。旧 Bot 从 Git 冻结策略代码，仅将引擎 API shim 和外部 import 指向双方共同的当前引擎；本评测不是两个历史整机引擎版本的对比。
- 使用真实地图、采矿、生产、寻路、弹道/伤害与胜负逻辑，通过 `GameFactory` / `Game.update` 无渲染运行，没有 mock 战斗或人为指定赢家。开启 short game，关闭超级武器、箱子和自动僵局判定，超时统一由 runner 处理。
- 早期 `tn01t2` 曾在 tick 4220 因缺失寻路图节点中止，记为错误。提交 `afdc560` 将此情形按不可达处理，经回归后重新跑完整 R1 同条件赛程；本表只使用修复引擎后的正式数据，未将原错误局记作胜局。
- 五组开发报告和两组 holdout 报告均无捕获运行错误；每份报告的四场 `tn01t2` 各有一条地图 `LightGreenTint=0,01` 数值格式 warning，已保留，不等于零 warning。

## 指标和结论的限制

- 开发赛程反复用于诊断和选择候选，仅一个种子、两张图、两个镜像阵营。五次对照的 40 局不是 40 个独立随机样本；另 16 局 holdout 虽采用新种子，仍沿用同图同阵营。位置配对和相同地图高度相关，不宜给出泛化胜率或将一次变化称为统计显著。尚未覆盖跨阵营对抗、其他国家、海空战地图、超级武器及真人对局。
- `creditsReceived` 包括矿业收入、卖建筑和取消生产退款，不能直接称为采矿收入。`creditsSpent` 也是现金流累计。反复取消生产会同时抬高这两个数；低资金 tick 可以比较生产压力，但不是完整的闲置时间。
- `damageDealt` 含 overkill 和对中立对象的伤害；`lostValue` 是销毁事件的造价合计，可能含卖出、非战斗销毁和败方清理。它们不能直接当作纯交战效率。数量上的击杀、存活兵力也不能替代单位构成、位置和射程。
- `processedActions` 是引擎打印过的动作条数，不是 APM，也不是执行成功且有效的操作数；一次命令可以影响多个单位。900 tick 的采样间隔约为 60 模拟秒，不能据采样独自推断取消生产或短暂寻路状态的因果。
- 自对打镜像和原状态一致性验证支持 runner 的可复现性；它们不证明图形客户端体验、联机同步、所有机制或人类难度已经通过验证。源码中的既有容错也意味着“捕获错误为零”不是不存在任何内部失败的证明。

## 代码与构建验证

最终保留代码的 `bun test` 为 **134 通过、13 跳过、0 失败**；`typecheck:entry`、`typecheck:server`、`bun --bun tsc -p e2e/tsconfig.ai-benchmark.json` 和 `bun run build` 均通过。跳过项依赖真实 PvPGN、资源目录或 HTTP 服务等测试环境，不计入通过数。独立的真实引擎对局、冻结快照加载、自对打镜像、布局观察器不改变状态以及缺失寻路节点回归，为策略评测提供额外验证。

最终选择 R4 是在这组受控 Bot 对战中保留已有收益，并撤回没有收益或退步的实验。仍需新地图、跨阵营和真人测试来检验更广范围的强度；现有结果不能证明人类完全无法获胜。
