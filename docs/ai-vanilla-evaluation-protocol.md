# 原版 RA2 战术测评协议

版本：2026-10-25。目的：区分“能执行一个战术”“某些场景有效”“完整对局比现有AI更强”。对应[打法调研](ai-vanilla-strategy-research.md)。本协议、[实验计划JSON](ai-vanilla-evaluation-plan.json)及其Git版本应在看到候选保留赛程结果前冻结。

## 1. 已知基线与评价问题

控制Bot固定为 `c18f77650e40b668064bdb913a75bebfa278f42b`。同一控制组已有三份独立432局报告：对原始14为416胜0负16平（96.30%）；对04为380胜36负16平（87.96%）；对0a为375胜29负28平（86.81%），均零运行错误。它们不是本次新打法的成绩。

每个实验预先选择一种主要变更，例如“相同造兵计划，只改狗随队站位”，或“保留微操，只改犀牛狗流生产预算”。必须同时回答：

用户在本协议提交后明确要求：犀牛配狗的主要验证对象是当前C18与加入该战术的新Bot直接对打。该要求优先，具体三组对照、开发赛程和判定见[P1实验登记](ai-rhino-dog-experiment.md)。下文对旧版0a的同对手比较作为辅助证据，不替代新旧当前Bot直接对抗。

1. 真实机制有没有发生，是否遵守资源、所有权、视野与命令限制？
2. 同初始条件下，启用/禁用这项变更产生什么差别？
3. 新版本是否胜过C18和上一个有效候选，并能应对独立的战术型对手？
4. 是否牺牲其他国家、地图、出生侧或防守能力，才换来目标场景的改善？

对原始Bot接近饱和，不要求每组都再提高3个百分点：**主要增益对手预注册为0a**；原始14和04用于守住已有能力。这避免要求本来100%的苏军国家再提高胜率。仍报告三个独立胜率，不混合版本或对手。

还要在每个假设开始前检查目标切片是否饱和：例如C18的伊拉克对三历史Bot均已100%，不能靠这些对手证明辐射守位进一步提升胜率。该阶段必须先在开发期建立并冻结更强或专门针对其弱点的战术对手，提交新的主要对手与验收计划，再看资格结果；旧三对手仍作能力守护。不能事后用展开次数或伤害代替未提高的主胜率。当前JSON的0a主要增益门槛适用于有提升空间的阶段，饱和阶段在完成新预注册前只能得到“未证明提升”。

## 2. 公平与可复现合同

每份正式结果记录完整候选、控制、对手提交和策略profile、引擎源码摘要、runner摘要、Bun/锁文件、规则/地图/地形摘要、出生点与玩家槽位、种子、选项和采样间隔。历史Bot由当前同一引擎加载；不是混比两个历史整机版本。

双方资金10000、额外部队0、引擎难度Normal（4）、30模拟分钟上限（27000tick）、无箱子、无超级武器、相同胜负条件；原始14使用normal策略，其他对手和候选使用brutal策略。profile不代表单边经济或伤害加成。

每配置交换出生点与玩家槽位。相同条件重复运行用于确定性检查，**不增加独立样本量**。观察器开/关保持完整最终状态一致；正常游戏决策只用模拟tick和游戏随机数。引擎、规则或runner变了，须重跑控制组，不能只跑新候选。

旧数据只有源码摘要、runner、全部条件和赛程完全相同时才能复用。两个CI提交仅文档或工作流不同，且实际游戏与runner摘要相同，可以明确记录后比较；提交ID相同不自动证明工作区干净。

## 3. 分层测评与成本控制

| 层级 | 问题与赛程 | 数量及结论范围 |
| --- | --- | --- |
| L0 回归 | 单元测试、报告完整性测试、类型检查、构建、正常难度与真实引擎确定性 | 证明实现和测评没有已知回归，不证明战力 |
| L1 机制 | 同兵数、同站位、换边的真实引擎场景；基础、受克制、失败/撤回条件 | 例如狗护坦克、辐射卡路、实际登卸车；预置单位不算完整经济收益 |
| L2 开发筛选 | 两图×3开发种子×4预注册阵营配对×2换边；候选和禁用版对同一对手各跑一次 | 每变体48局，两变体96局；用于淘汰和诊断，可调参，不能当保留验证 |
| L3 旧赛程回归 | 三个历史对手各432局；与同条件C18档案比较 | 候选1296局；旧三图/种子已经暴露，只是回归 |
| L4 保留验证 | 每个对手3组新种子；每组9国×其余8国×3图×2换边 | 每个Bot对每个对手1296局；三对手3888局。控制组同赛程也须有3888局，条件相同方可复用 |
| L5 直接与战术对抗 | 新Bot直接对C18、上一候选及独立战术对手；附镜像国家 | 单独预注册赛程，避免只会打一个旧Bot；不混进L4的三个基线胜率 |
| L6 新验证域 | 未调参新地图、原版海战、超武或多人 | 分开立项、校验地图与规则后再跑；当前不能宣称已经覆盖 |

只有较便宜的前一关有收益线索才进入昂贵下一关，不给每个参数变体都启动几千局矩阵。更换候选后保留失败资料，不删除弱局，也不复用已见过的资格种子继续选参。

L2示例配对：伊拉克/苏俄、伊拉克/美国、苏俄/法国、美国/伊拉克，选择需随研究假设预先记录；镜像与更多国家在后续扩展。开发的小样本只决定“值得继续测试”，不决定推广。

现有 `AI validation` 增加 `evaluation_set` 输入，默认仍为regression。每个run仍是三分组、432局及原始回执，保持现有完整性汇总器的约束；**不是把九个分组直接交给只支持三个分组的汇总器**。L4将三份完整、互不重叠档案交给新比较器，得到每个对手1296局、每配对18局、每国144局、每图432局。

例如在已包含本协议的执行分支上，加载冻结候选Bot：

```bash
gh workflow run ai.yml --repo chenxuan520/ra2web --ref research/ra2-vanilla-doctrines \
  -f full_matrix=true -f candidate_ref=FULL_FROZEN_CANDIDATE_SHA \
  -f baseline_ref=0a46d527995adc2411c04484de7336d63d4b0c5f \
  -f baseline_profile=brutal -f evaluation_set=qualification_a
```

`FULL_FROZEN_CANDIDATE_SHA`为示意占位，实际运行必须换成已经提交且通过前置检查的40位SHA；同候选再跑b/c。控制C18也在同一引擎、runner和资格赛程跑对照。原始14必须把baseline_profile设为normal。新比较器需要已完成原始回执核验后导出的精简档案，不能只下载网页上的汇总数字。

一旦查看资格结果并据此继续改Bot，这组种子就已暴露，下一次选候选必须提交新计划并换保留集。固定在仓库的种子不是保密集；通过冻结代码、运行前登记和不据其调参来控制偏差。

目前CI已能分别执行这些种子组并保留原始回执；跨run下载、核验和导出精简档案后，用第9节命令比较。还没有一个自动收集六条run并执行A/B比较的汇总job，不能把单条AI validation的绿色当成通过整个协议。

## 5. 必须保留的指标

**主指标**始终为胜 /（胜+负+平）；同时列出胜负平、运行错误、缺局、决胜局胜率。半分平局的得分如用于直接对抗判断，单列名称，不改叫主胜率。平均结束时间只在比较双方共同胜局或统一截断指标时解释，不能因为输得更早而称“更快”。

| 类别 | 指标与用途 | 注意事项 |
| --- | --- | --- |
| 总体 | 每个对手独立W/L/D、总胜率、决胜率、超时 | 不把错误、缺局、手工资产判定当平局/胜局 |
| 分组 | 国家、地图、国家×地图、对手国家、出生侧、种子 | 总胜率不能掩盖法国短图或某出生侧退步 |
| 运营 | 首炼厂/矿车/坦克、第二收入点、首有效压力、无收入时长、车辆队列停产、电力不足 | 总入账含退款，采矿收入未单独记录则标缺失 |
| 微操 | 实际射击与命中、单位失去输出时间、战斗伤害、战斗损失价值、低血存活、队形脱节 | 动作条数不是有效APM，销毁事件可能含出售/败方清理 |
| 狗坦协同 | 实际随队距离、敌炮目标、狗受炮伤、坦克存活/输出、狗消费、误冲/被碾压 | 狗死了不自动等于替坦克挡了一炮；对照实际弹道和点杀对手 |
| 科技 | 高科投入、第一批有用科技兵完成和到场、期间矿车/基地存活 | 不能只比较高科建成更早 |
| 多线 | 主力/骚扰组真实位置和重叠压力、目标损失、迫使敌军转移的可见证据、正面代价 | detach次数仅证明创建小队 |
| 辐射 | 可用机会、生产、到位、展开、双方受害、友军通道 | ownerless伤害不伪造攻击方；不把免疫矿车列作有效目标 |
| 巨炮/空军/伞兵 | 合法建成、供电、开火、实际命中；弹药/返航/损失；存活落地与接管 | 生成数量、起飞或调用技能都不等于有效收益 |
| 工程师/间谍/运输 | 真实登卸、抵达、入侵、所有权变化和原因、持有时间、收益、损失与撤回 | 核心建筑和CAOILD油井分开；无原因字段不能认领为工程师成功 |

现有遥测已提供部分生产、射击、碾压、所有权、运输和辐射事件；**开局计划转移、采矿专用现金流、狗护卫距离/挡弹归因、骚扰压力重叠、入侵来源与持有期等尚需补充**。没有这些字段时填“未提供”，不能默认0。观察器扩展后重跑同条件控制组并验证观察器不改变状态。

对可选战术还要报告“机会数量”：对手没有地面目标时0次辐射可以合理；在预注册的可用机会场景中持续0次则说明未发挥。机会判定在运行前定义，不能看见失败后改口称“不适合”。

## 6. 狗坦协同的具体实验

P1a先在固定兵力场景中，把完全相同的犀牛和狗交给“随队控制”和“原控制”，交换两侧；分自动选敌、明确点坦克、对方有反步兵/辐射、窄口/坡道、狗速度落后、狗被碾压等条件。初始兵力、血量、朝向、地形、种子、敌方控制都固定。

这能检验控制器本身，不能检验造狗是否值得。P1b再让两种完整Bot用相同10000资金正常采矿生产：一版现有步兵混编，一版犀牛狗流；记录狗投入挤掉了多少矿车、坦克和必要防守。额外加入“同样生产狗但关闭护卫”的消融版，分辨收益来自数量、生产节奏还是微操。

狗比例、首批坦克数量、矿车先后每次只扫有限参数，开发集选定后冻结。纯坦克、动员兵混编、犀牛带狗都必须有反例对手；不只打不会切换目标的静止靶子。相同单位数的机制实验和相同起始资金的运营实验分别报告，不能混称等成本。

## 7. 抵抗“只会打旧Bot”的战术对手

至少准备五类原版对手：持续犀牛狗压力、守矿反快攻、经济扩重工、保命转幻影/光棱、有限空军或多线骚扰。对手从正常资金生产，执行真实命令，保留视野；除L1机制场景外不预置免费军队。

这些对手的目标是暴露特定弱点，不需要每个都很强，也不根据候选临时修改。应独立实现/冻结后再跑，不让双方都共用同一段新狗微操而制造虚假的对抗证明。现有C18、0a和04不是这些独立战术对手的替代物。

对C18直接对打时，完整国家交叉仍是432局/种子组，可另外用 `ai-benchmark.ts --matchups` 跑9国镜像国家。三图×每图3新种子×9镜像×2换边为162局，独立记录，不冒充原432局赛程的一部分。直接对抗要报告W/L/D及胜+半平得分，按地图/种子块计算不确定性；得分95%区间下界未超过50%时，只能说未证明优于C18。该直接对抗统计与独立战术对手收集尚需在相应阶段实现，当前比较器只负责下一节的同对手A/B档案。

## 8. 判定规则与统计方法

机器规则在计划JSON中预注册，不能看到结果后下调：

1. **数据有效性。** 对局齐全、原始SHA和回执通过、相同条件、零运行错误；否则该批不可用于强度判断，先修具体错误。弱但完整的结果仍完整保存。
2. **绝对能力。** 三个历史对手各自总胜率≥80%，每国、每图≥70%。这些是工程门槛，不是人类战力等级。
3. **退步约束。** 相对同赛程C18，总胜率差点估计及95%区间下界均不低于−2个百分点；任一国家或地图点估计不得退步超过5个百分点。国家×地图和出生侧另作强制失败审阅，不用总数掩盖。
4. **主要增益。** 对预注册0a对手，在预注册目标国家上含平局胜率至少提高3个百分点，且其差值95%区间下界>0；原始14、04只要求守住能力与不退步，不要求对已100%的组继续提高。
5. **证据覆盖。** 资格集三图、每图至少3个新种子，保持所有国家配对和换边；只有3个“地图/种子”块的旧432局不据此给出可信增益区间。
6. **最终保留。** 除A/B比较外，还需真实机制/消融、直接对抗与独立战术对手、正常难度回归和失败样本审阅。比较器的promising只表示可进入下一验收，不是发布按钮。

对相同对手和配置的C18/候选结果逐局配对，主差值使用 `I(候选赢)−I(控制赢)`。为保留同图、同种子、双方换边与国家配对的关联，先按“地图×种子”聚合；在每张固定地图内部重采样种子块，5000次、固定统计随机种子，形成95%百分位区间。**不能将1296局假设成1296个独立伯努利样本。**

区间仅描述这些固定地图和种子的条件性差异；每图只有3个种子仍有限，不能称对所有地图统计显著，更不能外推真人。多次候选择优会产生选择偏差，因此只在开发集挑参数，锁定一个候选后一次性看资格集；再次改动就退役已暴露资格种子。遇到区间跨0、门槛边缘或目标场景稀少时判“证据不足”，按预先登记的新块补测，不只补自己输了的局。

## 9. 已实现的比较工具

[compare-ai-evaluations.py](../.github/scripts/compare-ai-evaluations.py)读取现有精简档案的metadata JSON和相邻games JSONL，验证游戏文件SHA、432局唯一身份/国家/地图/换边、错误与胜负理由、汇总一致性；合并多份档案时拒绝重复赛程、混版本、对手/profile/引擎/runner/资源差异。它支持原始normal对手，不会把所有历史profile强写成brutal。

脚本依赖原始artifact已经完成核验后才生成的 `receiptsVerified` 归档；**这不是重新下载并检查全部原始ZIP的工具**。原始核验沿用现有CI汇总与监控归档步骤，metadata摘要不能代替原报告。

```bash
# 三份控制档案与三份新候选档案，必须来自同一对手和资格a/b/c。
python3 .github/scripts/compare-ai-evaluations.py \
  --plan docs/ai-vanilla-evaluation-plan.json --hypothesis rhino_dog_micro \
  --control CONTROL_A.json CONTROL_B.json CONTROL_C.json \
  --trial TRIAL_A.json TRIAL_B.json TRIAL_C.json \
  --out comparison.json --require-improvement
```

对原始14、04的守护比较使用 `--require-non-regression`。不通过质量门槛时，先写完整comparison.json再以2退出；数据无效则以1退出。未传require选项时可以生成诊断报告，但退出0不代表战力达标。报告包含计划SHA、两个候选版本、对手、样本数、区间、各国/地图变化和失败项。

现有21项Python回归覆盖：相同策略不能被称为提升、单种子无法产生通过结论、完整配对效果、总体高但某国退步、混引擎/对手或地图摘要、档案篡改、缺换边、重复、运行错误、原始normal、饱和对手只要求不退步与种子泄漏等。合成数据只验证测评工具，不是实际战术结果。

## 10. CI与后台监控的交付标准

每条完整run必须读取回归、short/medium/long和report，保留原始逐局报告、日志、manifest、回执、结果JSON、矩阵CSV和门槛结果。资源/测试/运行失败与“完整有效但战力不够”分开；不能只重跑到变绿后删原失败证据。

合并资格档案时增加experiment ID、计划提交/摘要、假设ID、候选/控制/消融版本和每份run链接。最终中文报告按对手、国家、地图、出生侧列结果，解释真实特性与未提供项；取最差组和代表性败局/平局，不只展示胜局。

后台运行期间正常静默，失败和全结束各给出一次具体结论。未达标保存原因后回到开发阶段；达标也先完成报告和必要直接对抗，不凭机制fixture或原始Bot高胜率宣称战术成熟。
