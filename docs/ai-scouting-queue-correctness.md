# 侦察队列正确性与下一项付费实验

本项修复两个可由源码和失败测试证实的问题，不增加狗数量或认领新战术收益。

## L0：当前窄修复

公共起点 API 每次返回新的坐标对象，原实现按对象引用排除自己的起点，克隆坐标在未知/重新遮盖时会误入候选。两处入口现按 x/y 坐标排除自身，公共敌候选顺序保持。

原 `ScoutingManager.onAiUpdate` 在队列空时提前返回，连按时间扩展外围搜索的分支也不再执行。现在空队列仅跳过队首处理，继续原有扩圈规则：初始半径16，严格满足 `floor(tick/120)>queuedRadius+16`，首次为3960tick/半径33。已有队首的可见性处理、优先级、扫描顺序与RNG消费不改。

新增7项回归在旧源码先得到3通过/4失败；修复后与现有侦察/区域信息边界测试合跑18通过、0失败、110断言。测试含克隆自身坐标、空队列到时重填、未到时不扫描、全已探不生成，以及已有目标正常消费。该结果只证明正确性；真实引擎与冻结回执另行登记。

没有同时修永久目标重试、重复候选、命令节流或侦察补兵预算；这些影响行为取舍，应各自对照。`ffb438`是未证明收益的盟军建筑开局草稿，不是多狗侦察实现。当前仍是一个globalScout任务，不能把DOG总量当成已经多路线侦察。

## L1：固定投入的路线机制计划（尚未运行）

已有官方原版录像在部分开局显示现存3或4狗，也有城市局仍为3狗的不同情形。这支持调查侦察投入与职责，不能导出所有地图固定四狗。具体观察见[初批索引](ai-expert-observations.json)与[后续研究](ai-expert-decision-followup.md)。

最小机制实验分三臂：S1正常付费一狗顺序探点，作为数量/费用参考；S2正常付费两狗同目标；R2与S2相同生产政策、两狗各持不同公共未知目标。只用S2/R2归因路线分配，不同时改变退避、补兵、超时或生产反应。请求、实际受理、扣款、退款、出厂、在产分开，现金净变化不能当总狗花费。

先在真实短/中地图的可通两方向与第一方向受阻两类场景、物理出生/玩家槽换边下验证，公共候选保留空点，隐藏目标置换不得改变未揭露前指令。机制中预置相同生产设施必须明记；狗走正常队列和真实成本，禁止免费狗、补现金、额外敌情或改地形。重复同种子只查确定性，不扩大独立样本数。

最低遥测包含逐狗ID/目标分配、实际新增揭雾union与覆盖时间、首见敌类型、出厂与损失来源、真实费用/在产、重复命令，以及对手合法视图何时发现己方入口。不能从30tick静止推断等狗，也不能从900tick无任务推断零分配。无法逐狗归因的同tick揭雾只报全队union，不任意分功。

预置兵营机制不回答正常MCV开局的首重工/矿车/坦克延迟。进入L2正常经济实战时，需明确冻结基础源码与路线消融，隔离或固定未验证的盟军开局；当前C18及上一候选都在相同冻结引擎/API下对照。C18历史策略仍有隐藏起点读取时，另冻明确命名的信息受限控制，不能改写C18身份或将历史兼容对局当纯侦察归因。

L1机制可运行、开图更早和完整对局更强是三个不同结论，必须分别验证。新策略仍按[已登记测评计划](ai-vanilla-evaluation-plan.json)和曝光登记使用新的未见资格种子，保留全部失败条件与实际机会成本，不降低历史80/70/70和零运行错误门槛。
